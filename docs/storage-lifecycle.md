# 存储生命周期与图片清理（COS）

本文档说明图片在 COS 存储桶中的组织方式、过期清理规则，以及与图片中转服务器的协作约定。

## 部署拓扑

```
用户浏览器 ──(JSON/API，小流量)──► 应用服务器（4H8G / 12M，腾讯云，与桶同地域）
                                      │  AI 生图请求（经中转）
                                      ▼
                              中转服务器（2H4G / 200M，sub2api 协议网关）
                                      │
                                      ▼
                              上游 AI 服务（返回临时图片 URL / b64）
                                      │
应用服务器 ◄── 响应（临时 URL/b64）    │
      │                              │
      └── 应用侧转存：下载(入方向免费) + COS 内网上传(同地域免费) ──► COS 存储桶
                                                                        ▲
用户浏览器 ◄─────────图片直连（COS 域名，不走应用服务器）────────────────┘
```

- 中转服务器运行 sub2api（协议转换网关），**不做图片转存**；图片转存由应用侧完成；
- 应用服务器与 COS 桶同地域：在超管「系统设置 → 存储」打开**内网域名**开关
  （`cosForceInternalEndpoint`），**上传与服务端拉取**（图片代理、转存下载）都走
  `<bucket>.cos.<region>.tencentcos.cn` 内网域名——免费、不占 12M 公网出带宽，
  并避免 COS 公网下行流量费（约 0.5 元/GB）；下载上游图片为公网入方向，同样不计带宽；
- 图片**展示**走 COS 直连（`toImageSrc`，可带 imageMogr2 缩略参数）；
- 图片**下载**经 `/api/image/proxy` 同源代理（使浏览器 `download` 属性生效），为低频操作。

## 桶内目录规范（单桶 + 前缀，按企业分文件夹）

| 前缀 | 用途 | 是否过期 |
|---|---|---|
| `ref/` | 各企业用户上传的参考图 | 由 COS 生命周期规则决定 |
| `gen/` | 各企业 AI 生成图 | 由 COS 生命周期规则决定 |
| `gen/thumb/` | 生成图缩略图（在 gen/ 规则覆盖内） | 同 gen/ |
| `config/` | logo / 模型图标 / 模板图等配置图 | 建议永不过期 |

对象 key 规范（所有写入方必须遵守，含图片中转服务器直传）：

```
<前缀><enterpriseId>/<yyyy>/<mm>/<uuid>.<ext>
例：gen/6f2a...e9/2026/09/3b1f...c8.png
config/_platform/2026/09/74dd...bc.png   ← 平台级配置图（超管上传，无企业归属）
```

桶内每个前缀下**按企业 ID 分文件夹**，企业在控制台可按 `ref/<企业ID>/`、`gen/<企业ID>/` 浏览各自的文件。key 中必须含企业 ID 段（租户归属校验依赖它），UUID 保证不可猜测（公有读下的权限边界）。

## COS 生命周期规则配置（控制台）

过期与清理**完全由腾讯云 COS 控制台的生命周期规则管理**，应用侧不主动删除任何图片。在存储桶 → 基础配置 → 生命周期按需添加规则，参考：

| 规则名 | 覆盖前缀 | 动作 | 天数 |
|---|---|---|---|
| expire-ref | `ref/` | 删除对象 | 按需（如 30） |
| expire-gen | `gen/` | 删除对象 | 按需（如 30） |
| abort-multipart | 整桶 | 清理碎片（未完成分片上传） | 1 |

说明：

- 前缀在顶层（`ref/`、`gen/`），**各一条规则即可覆盖全部企业**，新增企业无需改动 COS 配置；
- `gen/` 规则自动覆盖 `gen/thumb/`，无需单独配置；
- `config/` 前缀**不要配置删除规则**（logo/图标属于长期资产）；
- 清理碎片规则可防止中转/客户端直传中断遗留的碎片持续计费；
- 调整保留期只需改 COS 控制台规则，代码无保留期常量。

## 过期图片的占位约定

- COS 生命周期规则删除对象后，**数据库中的 URL 一律保留**（历史记录不删）；
- 前端 `SmartImage` 组件在图片 404 时显示「图片已过期」占位图标（带 imageMogr2
  参数时会先降级重试原图）；所有展示可过期图片（ref/、gen/）的组件一律使用
  `SmartImage`，不要裸用 `<img>` / `next/image`。

## 已转存对象复用（预留能力）

`saveFromUrl` 内置「已转存对象直接复用」识别：URL 命中**本桶域名（canonical
或 cosBaseUrl，精确匹配）+ key 含本企业 ID 段**时原样返回、跳过「下载→重传」。
当前 sub2api 不做预转存，此路径不会命中（自动走正常转存，无任何影响）；若
未来在中转前加自建转存层，只要其按桶内 key 规范（`gen/<企业ID>/<yyyy>/<mm>/
<uuid>.<ext>`）上传并返回 canonical URL，应用会自动复用返回链接、图片字节
完全不经过应用服务器，无需改代码。跨租户段 / 无企业段 / http / 外域 URL
不会命中该识别（单测见 `storage-relay-skip.test.ts`）。
