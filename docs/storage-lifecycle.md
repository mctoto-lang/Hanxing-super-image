# 存储生命周期与图片清理（COS）

本文档说明图片在 COS 存储桶中的组织方式、过期清理规则，以及与图片中转服务器的协作约定。

## 部署拓扑

```
用户浏览器 ──(JSON/API，小流量)──► 应用服务器（4H8G / 12M）
                                      │  AI 生图请求
                                      ▼
                              图片中转服务器（2H4G / 200M）
                                      │  拉取上游图片 + 转存
                                      ▼
                              COS 存储桶（对象存储）
用户浏览器 ◄──────图片直连（COS / CDN 域名，不走应用服务器）──────────┘
```

- 带有图片的请求全部经中转服务器完成，中转负责把上游图片转存 COS，应用本体收到的响应即为可直接使用的图片链接；
- 图片**展示**走 COS 直连（`toImageSrc`，可带 imageMogr2 缩略参数），不占用应用服务器 12M 带宽；
- 图片**下载**经 `/api/image/proxy` 同源代理（使浏览器 `download` 属性生效），为低频操作。

## 桶内目录规范（单桶 + 前缀）

| 前缀 | 用途 | 是否过期 | 保留期 |
|---|---|---|---|
| `ref/` | 用户上传的参考图 | 会过期 | **30 天** |
| `gen/` | AI 生成图 | 会过期 | **30 天** |
| `gen/thumb/` | 生成图缩略图（在 gen/ 规则覆盖内） | 会过期 | **30 天** |
| `config/` | logo / 模型图标 / 模板图等配置图 | **永不过期** | — |

对象 key 规范（所有写入方必须遵守，含图片中转服务器直传）：

```
<前缀><enterpriseId>/<yyyy>/<mm>/<uuid>.<ext>
例：gen/6f2a...e9/2026/09/3b1f...c8.png
```

key 中必须含企业 ID 段（租户归属校验依赖它），UUID 保证不可猜测（公有读下的权限边界）。

## COS 生命周期规则配置（控制台）

存储桶 → 基础配置 → 生命周期，添加以下规则：

| 规则名 | 覆盖前缀 | 动作 | 天数 |
|---|---|---|---|
| expire-ref | `ref/` | 删除对象 | 30 |
| expire-gen | `gen/` | 删除对象 | 30 |
| abort-multipart | 整桶 | 清理碎片（未完成分片上传） | 1 |

说明：

- `gen/` 规则自动覆盖 `gen/thumb/`，无需单独配置；
- `config/` 前缀**不配置任何删除规则**；
- 清理碎片规则可防止中转/客户端直传中断遗留的碎片持续计费；
- 可选成本优化：对 `ref/`（消费发生在生成后几分钟）可将保留期缩短到 7 天——需与代码常量同步（见下）。

## 修改保留期的正确姿势（两处同步）

保留期固定在代码常量 `IMAGE_RETENTION`（`src/lib/storage/config.ts`）：

```ts
export const IMAGE_RETENTION: ImageRetentionConfig = {
  referenceRetainDays: 30,
  generateRetainDays: 30,
}
```

修改保留期时**必须同步**：

1. 代码常量 `IMAGE_RETENTION`（应用侧 cleanup cron 依据它清理）；
2. COS 控制台生命周期规则（对象删除主路径）。

超管「平台管理 → 系统设置 → 图片保留策略」为只读展示，不可在线修改。

## 应用侧清理与占位

- **主路径**：COS 生命周期规则自动删除过期对象；
- **兜底**：`POST /api/cron/cleanup-images`（宿主机 cron 触发，`CRON_SECRET` 鉴权）按 `IMAGE_RETENTION` 删除本地存储对象 / COS 对象（幂等，与生命周期规则重叠无害），建议每日一次；
- 两者均**只删对象、不删数据库中的 URL**：历史记录保留，前端 `SmartImage` 在对象 404 时显示「图片已过期」占位图标。

## 图片中转服务器约定

中转服务器直接向 COS 上传时：

1. 沿用上文 key 规范（前缀 + 企业 ID + 年月 + UUID），否则生命周期规则与租户校验失效；
2. 若中转服务器与 COS 同地域（腾讯云内网），使用内网域名 `<bucket>.cos.<region>.tencentcos.cn` 上传（免流量费、不占公网带宽）——应用侧对应开关为存储设置中的「内网上传」（`cosForceInternalEndpoint`）；
3. 中转返回给应用的图片链接使用公网规范域名 `<bucket>.cos.<region>.myqcloud.com`（应用的可信下载白名单与 `toImageSrc` 直连均识别该域名），或将中转域名加入存储设置的「额外可信下载域名」。
